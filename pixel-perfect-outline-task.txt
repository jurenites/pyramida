Why Decouple Simulation and Rendering?
When you tie your game logic to Godot's visual nodes (like attaching a script with heavy math to every single citizen or every block of terrain), your frame rate will tank when you have thousands of objects. By decoupling, you get:

Uncapped FPS: Your visual engine can run at 144+ FPS (_process), interpolating positions smoothly, while your heavy city-building logistics simulation runs at a steady, separate tick rate (e.g., 20 or 30 ticks per second).

Headless Scaling: You can calculate massive chunks of your world (water overflowing, citizens routing logistics) purely in C# data arrays without the GPU ever needing to know about it until that chunk comes into the camera's view.

Data-Oriented Design: You can use C# Structs and native arrays for your grid/voxel data, which is incredibly fast for CPU caching.

It uses a cross-sampling technique (similar to a Sobel filter) to detect sudden changes in depth (object boundaries) and normals (sharp corners) to draw a crisp outline. Because it uses filter_nearest, it perfectly preserves the blocky, pixelated look required for a Minecraft-like voxel aesthetic.The Depth/Normal Outline ShaderCreate a new ShaderMaterial, assign a new Shader, and paste this code:OpenGL Shading Languageshader_type spatial;
render_mode unshaded, fog_disabled, depth_draw_never, cull_disabled;

// Using filter_nearest is critical for the crisp 3D pixel art aesthetic
uniform sampler2D screen_texture : hint_screen_texture, repeat_disable, filter_nearest;
uniform sampler2D depth_texture : hint_depth_texture, repeat_disable, filter_nearest;
uniform sampler2D normal_texture : hint_normal_roughness_texture, repeat_disable, filter_nearest;

uniform vec3 outline_color : source_color = vec3(0.05, 0.05, 0.05);
uniform float outline_thickness : hint_range(0.0, 5.0) = 1.0;

// Depth variables (detects objects overlapping other objects)
uniform float depth_threshold : hint_range(0.0, 1.0) = 0.01;
uniform float depth_multiplier : hint_range(0.0, 100.0) = 1.0;

// Normal variables (detects sharp corners within the same object)
uniform float normal_threshold : hint_range(0.0, 2.0) = 0.5;

void vertex() {
	// Maps the mesh directly to clip space to cover the entire screen
	POSITION = vec4(VERTEX.xy, 1.0, 1.0);
}

void fragment() {
	vec2 pixel_size = outline_thickness / VIEWPORT_SIZE;

	// 1. Sample the base screen color
	vec3 original_color = texture(screen_texture, SCREEN_UV).rgb;

	// 2. Cross-sample depth (center, up, down, left, right)
	float d_center = texture(depth_texture, SCREEN_UV).x;
	float d_up     = texture(depth_texture, SCREEN_UV + vec2(0.0, -pixel_size.y)).x;
	float d_down   = texture(depth_texture, SCREEN_UV + vec2(0.0, pixel_size.y)).x;
	float d_left   = texture(depth_texture, SCREEN_UV + vec2(-pixel_size.x, 0.0)).x;
	float d_right  = texture(depth_texture, SCREEN_UV + vec2(pixel_size.x, 0.0)).x;

	// Calculate depth difference to find edges
	float depth_diff = abs(d_center - d_up) + abs(d_center - d_down) + abs(d_center - d_left) + abs(d_center - d_right);
	depth_diff *= depth_multiplier;

	// 3. Cross-sample normals
	vec3 n_center = texture(normal_texture, SCREEN_UV).xyz;
	vec3 n_up     = texture(normal_texture, SCREEN_UV + vec2(0.0, -pixel_size.y)).xyz;
	vec3 n_down   = texture(normal_texture, SCREEN_UV + vec2(0.0, pixel_size.y)).xyz;
	vec3 n_left   = texture(normal_texture, SCREEN_UV + vec2(-pixel_size.x, 0.0)).xyz;
	vec3 n_right  = texture(normal_texture, SCREEN_UV + vec2(pixel_size.x, 0.0)).xyz;

	// Calculate normal difference to find sharp corners
	float normal_diff = length(n_center - n_up) + length(n_center - n_down) + length(n_center - n_left) + length(n_center - n_right);

	// 4. Evaluate if the pixel is on an edge
	bool is_depth_edge = depth_diff > depth_threshold;
	bool is_normal_edge = normal_diff > normal_threshold;

	if (is_depth_edge || is_normal_edge) {
		ALBEDO = outline_color;
	} else {
		ALBEDO = original_color;
	}
}

This prevents your screen quad from casting a massive shadow over your terrain.5.Apply the ShaderMaterial:Scroll down to the Surface Material Override in the MeshInstance3D inspector, create a new ShaderMaterial, and paste the provided code into a new shader.Tuning for Voxel TerrainBecause you are building out a blocky, terraced environment, the Normal Threshold parameter will be your most important setting.If the normal_threshold is set too low (e.g., 0.1), the shader will draw an outline on every single block edge of your terrain, which quickly creates visual clutter. Adjusting this slider up towards 0.5 or 1.0 will allow flat surfaces of adjacent blocks to blend together, only drawing outlines when the geometry actually changes direction (like the edge of a cliff or a tree trunk).
